Step 1 — Security (Do First)
1
Rotate Exposed Secrets
Security Risk
⚠
Real credentials are committed in proxy/.env. Even though this repo may be private, these are Continue.dev's credentials that should not be used. Rotate them now.
Rotate Google OAuth credentials
Go to Google Cloud Console → APIs & Services → Credentials
• Create a new OAuth 2.0 Client ID (or rotate the existing one)
• Copy the new Client ID and Client Secret
• Update proxy/.env with new values:
SSO_CLIENT_ID=<your-new-google-client-id>.apps.googleusercontent.com SSO_CLIENT_SECRET=<your-new-google-client-secret>
Generate new MASTER_KEY
Run in terminal:
openssl rand -hex 32
Copy the output and update proxy/.env:
MASTER_KEY=<paste-the-64-char-hex-string>
Ensure proxy/.env is gitignored
Run:
# Check if .env is tracked by git git ls-files proxy/.env # If it shows output, remove from tracking (keeps the local file) git rm --cached proxy/.env
Verify .gitignore has proxy/.env or *.env
Step 2 — Domain & Hosting

Register Domain & Set Up DNS
When Deploying

TypeNameValuePurpose

MX@<mail-provider>Email (security@ address)
Set up SSL/TLS certificates
Use Let's Encrypt (free) via Certbot, or Cloudflare (automatic).
Ensure certs cover: ai-firewall.dev, api.ai-firewall.dev, docs.ai-firewall.dev
Update BRAND URLs if domain is different
If you chose a domain other than ai-firewall.dev, update packages/brand/src/index.ts:
appUrl: "https://your-domain.com", apiUrl: "https://api.your-domain.com", docsUrl: "https://docs.your-domain.com",
Then rebuild: cd packages/brand && npm run build
Then ask Claude to update the remaining 160 hardcoded references.

Required for login

WorkOS handles user authentication (login/signup). Currently hardcoded with Continue.dev's client IDs. You need your own.

In WorkOS Dashboard → Authentication → Create Application
• Set redirect URI to: https://ai-firewall.dev/auth/callback (or your domain)

• Copy the Client ID

Tell Claude: "Replace the WorkOS client IDs in core/control-plane/env.ts with environment variables"

Set Up Google OAuth (SSO)
For Google login

Google Cloud Console → Create Credentials → OAuth client ID
• Application type: Web application
• Name: AI Firewall

https://api.your-domain/api/auth/sso/callback http://localhost:8080/api/auth/sso/callback (for local dev)

In Google Cloud Console → OAuth consent screen:
• App name: AI Firewall
• User support email: your email

Deploy proxy server
The proxy is a Fastify Node.js server. Deploy it with these env vars:
PORT=8080 NODE_ENV=production MASTER_KEY=<your-master-key> SSO_CLIENT_ID=<google-client-id> SSO_CLIENT_SECRET=<google-client-secret> DB_PATH=./data/firewall.db
Build: cd proxy && npm run build && npm start
Deploy GUI (static site)
Build: cd gui && npm run build
Deploy the gui/dist/ folder to any static host (Vercel, Netlify, Cloudflare Pages, or your own nginx)
Set up reverse proxy with TLS
Use nginx or Caddy to route:
• api.ai-firewall.dev → localhost:8080 (proxy server)
• ai-firewall.dev → static files (GUI)
• docs.ai-firewall.dev → docs hosting
