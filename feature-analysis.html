Feature Classification Summary

Category A — Directly Reusable (14)

Can be used with zero or minimal changes. No conflict with Continue or Firewall.

  • Continue.dev tools (10): readFile, globSearch, grepSearch, runTerminalCommand, searchWeb, fetchUrlContent, createNewFile, viewDiff, memory, planTool, worktree
  • Continue.dev infra (3): countTokens.ts, streamChat.ts, MCPConnection.ts
  • Proxy intelligence (1): tokenCounter.ts (already uses tiktoken WASM)

Rule: DO NOT rebuild these. Use as-is. Only add firewall interception wrappers.

Category B — Needs Adaptation (28)

Must be modified to route through firewall proxy, respect policy engine, or integrate with Continue APIs.

  • Tools needing scan wiring (6): FileEdit, TaskMgmt, Agent, Notebook, AskUser, SendMessage
  • Services needing proxy integration (8): Compaction, Permissions, Commands, CostTracking, Config, Sessions, Approval, SmartRouting
  • Already built (3): ResponseScanning, SmartRouter, ApprovalWorkflow — extend only
  • Port + adapt (11): ToolSearch, OAuth, CostBadge wiring, SessionHistory, etc.

Rule: Every adapted feature MUST route LLM calls through /v1/chat/completions and file ops through /api/scan/file.

Category C — Must Be Rebuilt (26)

Tightly coupled to Claude's internal infra (Anthropic SDK, GrowthBook, CCR) or requires entirely new architecture.

  • Multi-agent (3): Coordinator, DreamTask, MemoryExtraction — coupled to claude-code's AppState
  • Extensibility (3): Skills, Plugins, Hooks — no equivalent exists
  • UI (4): PermissionDialogs, DiffComponents, OnboardingWizard, TerminalUI
  • Enterprise (5): FeatureFlags, TeamMemSync, Telemetry, SettingsSync, Bridge
  • Tools (3): Sandbox, LSP, Cron — platform-specific
  • Other (8): Suggestions, various commands, config migrations

Rule: Rebuild using our patterns (Fastify routes, Zod schemas, SQLite, Redux Toolkit). Never import from claude-code directly.

Non-Negotiable Security Rules

  • EVERY LLM call routes through POST /v1/chat/completions (proxy intercepts)
  • EVERY file read/write routes through /api/scan/file or uses fileScanService.scanFileContent()
  • EVERY MCP tool call routes through /v1/mcp/tools/call (mcpScanPipeline)
  • EVERY agent prompt gets independent scan context (no shared scan results between parent/child)
  • EVERY LLM response gets scanned before reaching user (responseScanner middleware)
  • NEVER bypass rate limits for automated features (cron, dream, coordinator workers)

Implementation: Context Reduction Pipeline

User Input
  → Token Count (real tiktoken via proxy/src/gateway/tokenCounter.ts)
  → IF tokens > model_context * 0.75:
      → Context Compaction (compactService.ts)
        → Time-based: clear tool results older than gap threshold
        → Count-based: keep last N tool results
        → Summary: compress old assistant messages to 1-line summaries
      → Recount tokens
  → IF still over:
      → Set X-AF-Context-Overflow header (NEVER auto-truncate)
      → Client prompts user: "Context is 120% of limit. Compact?"
  → Proceed with optimized context

1. Planner Agent

Source: EnterPlanModeTool + planTool.ts (Continue)

Behavior: Enter plan mode → restrict tools to read-only → design approach → exit plan mode → hand off to Executor

Firewall: Plan text scanned via preflight. No file writes in plan mode.

2. Context Collector Agent

Source: GlobTool + GrepTool + WebSearchTool + MCP resources

Behavior: Grep-first strategy (search before read). Read only relevant chunks. Minimize tokens sent to LLM.

Firewall: File reads through /api/scan/file. Web fetches through MCP scan pipeline.

3. Security Scanner Agent

Source: @ai-firewall/scanner package (our unique advantage)

Behavior: Runs pre/post scan on all I/O. Enforces policy. Sets X-AF-* headers.

Firewall: IS the firewall. All 9 layers applied.

4. Reducer Agent

Source: compactService.ts + claude-code's microcompact algorithm

Behavior: Monitor token usage. Compact old messages. Budget allocation per component.

Firewall: Compacted text re-scanned if new context added.

5. Executor Agent

Source: All write tools (FileEdit, FileWrite, BashTool, NotebookEdit)

Behavior: Execute plan. Permission check per tool call. Background mode for long tasks.

Firewall: Every tool call through permission layer. Every file write through scan.

6. Validator Agent

Source: DreamTask pattern + test execution

Behavior: Run tests after changes. Verify no regressions. Consolidate learnings to memory.

Firewall: Test outputs scanned. Memory writes scanned before persist.

MCP Security Gateway Flow

Agent requests MCP tool call
  → POST /v1/mcp/tools/call (proxy route)
  → Serialize arguments to text
  → scanMcpContent(text, "input") ← STRICTER weights (+40 critical vs +20)
  → IF BLOCK → 403 + audit log
  → IF REDACT → sanitize args
  → Forward to MCP server (via Continue's MCPConnection)
  → Receive response
  → scanMcpContent(response, "output") ← Same strict weights
  → IF secrets in output → REDACT before returning to agent
  → Log to mcp_audit table
  → Return with X-AF-MCP-* headers
