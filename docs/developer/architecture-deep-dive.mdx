## SOLID Principles Applied

### Single Responsibility (SRP)

Every module has exactly **one reason to change**:

```
wsManager.ts       → Changes only when WebSocket protocol changes
approvalService.ts → Changes only when approval workflow changes
notificationService.ts → Changes only when dispatch logic changes
```

They don't know about each other. The route handler (approval.route.ts) wires them together.

### Open/Closed (OCP)

Add new capabilities without modifying existing code:

```typescript
// Add a new scanner pattern — edit patterns.ts only, scanners unchanged:
export const secretPatterns = [
  ...existingPatterns,
  { type: "NEW_SECRET_TYPE", regex: /new-pattern/g, severity: "high" },
];

// Add a new notification channel — implement interface, register in server.ts:
export const slackChannel: NotificationChannelHandler = {
  type: "slack",
  async send(userId, event, config) { /* ... */ }
};
registerChannel(slackChannel);  // In server.ts
```

### Dependency Inversion (DIP)

Routes depend on **interfaces**, not implementations:

```typescript
// approval.route.ts depends on:
import { getPendingApprovals, resolveApproval } from "../services/approvalService";
// NOT on: import db from "../db/database" (implementation detail)

// Cache consumers depend on CacheAdapter interface:
const cache = await getCache();  // Returns memory or Valkey — caller doesn't know
await cache.set("key", "value", 300);
```

### Interface Segregation (ISP)

`@ai-firewall/scanner` exports **only scanner types** — no policy, auth, or gateway types:

```typescript
// Consumer only imports what they need:
import { scanSecrets, type SecretScanResult } from "@ai-firewall/scanner";
// NOT: import { PolicyConfig, User, Provider, ... }
```

## How to Add a New Feature

### New Scanner Pattern

1. Edit `packages/scanner/src/patterns.ts` — add pattern to `secretPatterns` or `piiPatterns`
2. Rebuild: `cd packages/scanner && npm run build`
3. Run tests: `cd proxy && npm run test:unit` — existing tests verify the pipeline
4. Done. No other files need changes (OCP).

### New Prompt Injection Pattern

1. Edit `packages/scanner/src/promptInjectionScanner.ts` — add to `INJECTION_PATTERNS` array
2. Choose weight carefully: 15 (low confidence) to 35 (high confidence). Threshold is 60, so single pattern (max 35) never triggers alone.
3. Add true positive + true negative tests
4. Rebuild scanner package: `cd packages/scanner && npm run build`

### New Unicode Confusable

1. Edit `packages/scanner/src/unicodeNormalizer.ts` — add to `CONFUSABLE_MAP`
2. Add test in `proxy/src/test/unicodeNormalizer.test.ts`
3. Rebuild scanner package

### New Proxy Route

1. Create `proxy/src/routes/yourFeature.route.ts`
2. Define Zod schema in `proxy/src/schemas/` (don't inline)
3. Register in `proxy/src/server.ts` — add before the `/v1/*` catch-all
4. Add types to `proxy/src/types/index.ts` if needed
5. Write tests in `proxy/src/test/yourFeature.test.ts`
6. Register tests in `proxy/src/test/run-tests.ts`

### New Notification Channel

1. Create `proxy/src/notifications/channels/slack.ts`
2. Implement `NotificationChannelHandler` interface
3. Register in `server.ts`: `registerChannel(slackChannel)`
4. No other files need changes (OCP + DIP).

### New MCP Server

1. Build as a standalone process in `packages/mcp-servers/src/servers/`
2. Use `@ai-firewall/scanner` for scanning (not proxy internals)
3. Register in MCP config — existing MCPConnection client connects automatically
4. All tool calls scan through the gateway route

## Database Schema

22 tables in SQLite (WAL mode). Key tables:

| Table | Phase | Rows Grow By |
|-------|-------|-------------|
| `logs` | 1 | Every LLM request |
| `usage_logs` | 4 | Every LLM request (tokens + cost) |
| `file_scan_cache` | P2 | Every unique file scanned |
| `mcp_audit` | P3 | Every MCP tool call |
| `approval_requests` | P4 | Every high-risk action |
| `webhook_deliveries` | P5 | Every webhook event (with retries) |

All tables use `INTEGER PRIMARY KEY AUTOINCREMENT` and `INTEGER` timestamps (ms since epoch).

## Environment-Aware GUI

The GUI detects whether it's running inside an IDE (VS Code/JetBrains) or as a standalone web dashboard:

```typescript
import { isInIde, isStandaloneWeb } from "../util";
```

**IDE mode** (VS Code webview): Only shows Chat, History, Config, Stats. Admin pages redirect to home.
**Web mode** (standalone dashboard): Shows all pages + persistent sidebar navigation (Security, Roles, Org, Teams, Agents).

Detection uses `localStorage.ide` — set to `"vscode"` or `"jetbrains"` by the extension, absent in standalone web.

## Design Decisions

| Decision | Why |
|---------|-----|
| SQLite not Postgres (default) | Local-first, zero setup, single-file DB. Postgres optional via Phase 5 adapter. |
| Pure-function scanners | No side effects = safe to use anywhere (proxy, MCP servers, CLI, tests) |
| Advisory context window | OWASP: never silently modify user input. Warn via headers, user decides. |
| Cost routing disabled by default | New features are opt-in via policy.json. Never surprise the user. |
| Scanner re-exports in proxy | Backward compatibility. All existing imports still work after extraction. |
| tini in Docker | Node.js doesn't handle SIGTERM as PID 1. Required for K8s graceful shutdown. |
| bookworm-slim not alpine | better-sqlite3 is native C++. musl libc (Alpine) has documented segfault risks. |
| Ed25519 for licenses | Offline verification, no phone-home. Same pattern as GitLab/n8n. |
| Valkey not Redis | Redis SSPL license. Valkey is BSD-3, Linux Foundation backed. ioredis works unchanged. |
