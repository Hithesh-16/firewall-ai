## System Overview

AI Firewall is a monorepo with four main components:

```
continue-main/
├── proxy/              Security proxy (Fastify, port 8080)
├── core/               Agent engine (60+ LLM providers, 26 tools)
├── gui/                React + Redux webview UI
├── extensions/         VS Code, JetBrains, CLI
└── packages/
    └── scanner/        Shared security scanners (@ai-firewall/scanner)
```

The **proxy** is the security boundary. Every LLM request, file read, and MCP tool call passes through it.

## Request Flow

Every chat request follows this pipeline:

<Steps>
<Step title="Token Estimation">
Real token counting via `js-tiktoken` (WASM BPE tokenizer). Falls back to character heuristic if WASM fails. Sets `X-AF-Input-Tokens` header.
</Step>

<Step title="Scanner Pipeline">
Six scanners run in sequence:
1. **Secret Scanner** — 12 regex patterns (AWS keys, private keys, JWTs, DB URLs, GitHub tokens, etc.)
2. **PII Scanner** — 7 patterns (email, phone, SSN, Aadhaar, PAN, credit card, IP)
3. **Entropy Scanner** — Shannon entropy analysis for high-entropy tokens near context keywords
4. **Context Scanner** — Adjusts severity based on file paths (test files get downgraded, auth files upgraded)
5. **Prompt Injection Scanner** — 13 jailbreak/injection pattern categories
6. **Policy Engine** — Weighted risk scoring → BLOCK / REDACT / ALLOW decision
</Step>

<Step title="Context Window Advisory">
Checks if total tokens fit within the model's context window. **Never truncates** — sets `X-AF-Context-Overflow` header and lets the client warn the user. The request proceeds regardless.
</Step>

<Step title="Cost-Aware Routing (opt-in)">
If enabled in `policy.json`, routes requests to cheaper models based on estimated cost. Disabled by default — falls through to risk-based routing.
</Step>

<Step title="Provider Adapter">
Formats the request for the target provider (OpenAI, Anthropic, Gemini, Ollama) and forwards. Response is scanned for leaks on the way back.
</Step>

<Step title="Audit + Headers">
Logs to SQLite, records token usage and cost, returns response with `X-AF-*` scan metadata headers.
</Step>
</Steps>

## Response Headers

Every proxied response includes these headers:

| Header | Value | Description |
|--------|-------|-------------|
| `X-AF-Action` | ALLOW/BLOCK/REDACT | Policy decision |
| `X-AF-Risk-Score` | 0-100 | Aggregate risk score |
| `X-AF-Secrets-Count` | number | Secrets detected |
| `X-AF-PII-Count` | number | PII items detected |
| `X-AF-Findings` | JSON array | Detected items with type, severity, category, masked value (max 20) |
| `X-AF-Redacted-Types` | comma-separated | Types of redacted items (e.g., `AWS_KEY,EMAIL`) |
| `X-AF-Input-Tokens` | number | Real tiktoken count |
| `X-AF-Estimated-Cost` | number | Pre-request cost estimate |
| `X-AF-Token-Method` | tiktoken/heuristic | Which tokenizer was used |
| `X-AF-Context-Overflow` | true | Only when over context limit |
| `X-AF-Context-Warning` | string | Advisory message |

## Database

SQLite with WAL mode. 22 tables covering audit logs, auth, providers, credits, file scan cache, MCP audit, approval workflow, and session tracking.

<Tip>
The proxy is designed as a **gateway, not a controller**. It informs via headers — never silently modifies your prompts, truncates your context, or blocks oversized requests. The client (extension/CLI) reads headers and lets you decide.

**Exception:** File reads are actively enforced. The `readFile` tool in both CLI and core calls `POST /api/scan/file` before reading. If the proxy returns BLOCK, the file is never read. If it returns REDACT, the sanitized content is used instead. This is the one path where the proxy actively prevents access rather than just informing.
</Tip>

## Advanced Security Layers

Beyond the core scanner pipeline, the proxy includes advanced security modules:

| Layer | Module | Purpose |
|-------|--------|---------|
| Multi-Turn Tracking | `multiTurnTracker.ts` | Detects escalation, pivot, and repetition patterns across conversation turns |
| RAG Injection Shield | `ragScanner.ts` | Scans documents/chunks before RAG ingestion (17 patterns) |
| Intent Clustering | `intentCluster.ts` | SimHash fingerprinting detects coordinated attacks from multiple users |
| Behavioral Fingerprinting | `behaviorFingerprint.ts` | Per-user z-score anomaly detection |
| Prompt Confidentiality | `promptConfidentiality.ts` | Blocks system prompt extraction attempts (22 patterns) |
| Cross-Model Correlation | `crossModelCorrelation.ts` | Groups attacks across GPT-4/Claude/Gemini into unified incidents |
| Multi-Modal Scanner | `multiModalScanner.ts` | Scans images (OCR), audio transcripts, structured files |
| Grounding Engine | `groundingEngine.ts` | Cross-references LLM outputs against source documents |
| Embedding Detector | `embeddingDetector.ts` | ML-based injection detection (60-dim features, KNN + centroid) |
| Federated Intelligence | `federatedIntel.ts` | Privacy-preserving threat signature sharing via LSH/MinHash |
| Supply Chain Integrity | `supplyChain.ts` | Model hash verification, backdoor scanning, behavior drift |
| Compliance Mapper | `complianceMapper.ts` | Maps events to GDPR, EU AI Act, HIPAA, NIST, SOC 2, ISO 42001 |
| Business Logic DSL | `businessLogicDsl.ts` | Org-specific rule engine (9 operators, 5 actions) |
| Red Team Agent | `redTeamAgent.ts` | 62 adversarial probes across 10 categories |
| Shadow AI Detector | `shadowAiDetector.ts` | Detects unapproved LLM API usage (32 known endpoints) |
| PII Vault | `piiVault.ts` | Reversible PII tokenization (replace before LLM, restore after) |

See [Advanced Scanners](/security/advanced-scanners), [Advanced Features](/proxy/advanced-features), and the [Advanced API Reference](/api-reference/advanced-endpoints) for full details.

## Design Principles

1. **Proxy is a gateway, not a controller** — informs, never modifies silently
2. **Loosely coupled** — every feature toggleable via `policy.json`
3. **Never truncate automatically** — warn via headers, let the user decide
4. **Scan, don't manage** — proxy scans content, doesn't store/manage files
5. **SOLID everywhere** — SRP per module, OCP via patterns, DIP via interfaces
